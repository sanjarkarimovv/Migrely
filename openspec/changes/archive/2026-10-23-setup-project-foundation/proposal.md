# Proposal

## Why

Migrely has an approved BRD (docs/BRD.md) but no runnable codebase. Every feature change after this one needs the same
foundation: a Clean Architecture project generated by `cag`, a documented project profile, an app shell that opens on a
home destination, a dark photophobia-safe theme and an automated quality gate. Building that once, before the first
feature, keeps all later changes small and consistent.

## What Changes

- Adopt the `cag` 0.4.1 scaffold already generated in the repository root (applicationId `com.migrely.app`, ktlint, detekt,
  Hilt) and make it build and pass its gates.
- Write `docs/ARCHITECTURE.md`, the project profile required by the clean-arch skill (module layout, navigation binding,
  network binding, exception routing, UI state holder, lint gate, test libraries, known deviations).
- Replace the generated `samplefeature` module set with a `home` feature generated by `cag --new-feature`, showing an app
  shell home screen.
- Add navigation to `:app` following the skill binding chosen in the design (routes, nav host, navigation event mapper).
- Replace the generated theme with a dark-first, low-brightness Material 3 theme and keep it as the default.
- Raise `minSdk` to 26 (BRD section 10); set the app name to "Migrely" and the version to `0.1.0`.
- Install the skill's Konsist architecture tests in `:app` unit tests.
- Add a GitHub Actions workflow that runs the build, unit tests, Konsist tests, ktlint and detekt.

Out of scope:
- Any migraine feature (attack logging, history, medications and the rest). These are changes 1–12 in BRD section 13.
- Room database, DataStore, billing, analytics and any datasource implementation.
- Release signing, R8 minification, store listing and Play Console setup (change 13, `prepare-release`).
- Auto Backup rules (change 7, `add-data-export-import`).
- Upgrading to AGP 9, Kotlin 2.4 and Navigation 3 beyond what the design decides for this change.

## Capabilities

### New Capabilities

- `app-shell`: launching the app, the default theme, and what the app must not do on first launch (no runtime permission
  prompts, no network calls). Covers BRD EC-UX-01, EC-REM-01, ADR-11 and principle 4 (health data never leaves the
  device).

### Modified Capabilities

None. This is the first change in the project.

## Impact

- **Code:** root Gradle files, `gradle/libs.versions.toml`, `:app` (activity, theme, navigation, DI), new
  `:features:home:{domain,presentation,data,ui}`, removed `:features:samplefeature:*`, `app/src/test` architecture tests.
- **Docs:** new `docs/ARCHITECTURE.md`. The BRD module map (section 12) is aligned with the generated layout.
- **Tooling:** `.github/workflows/ci.yml`, `.gitignore`.
- **Dependencies:** Konsist added as a test dependency. The design decides the toolchain versions.
- **BRD references:** ADR-01, ADR-02, ADR-03, ADR-11, ADR-12, ADR-13, D9, D13, EC-UX-01, EC-REM-01, NFR (minSdk 26).

# Design

## Context

The repository root holds a project generated by `cag` 0.4.1 (`--new-project --name=Migrely --package=com.migrely.app
--ktlint --detekt`). An identical scaffold built and passed its unit tests unchanged on 2026-10-23, so the generator
defaults are a known-good starting point.

The generated toolchain is Gradle 8.14.3, AGP 8.13.0, Kotlin 2.2.20, Compose BOM 2025.10.00, Hilt 2.57.2,
navigation-compose 2.9.5 and compile/target SDK 36. The scaffold also contains:

- `:architecture:{domain,presentation,presentation-test,ui,instrumentation-test}`
- `:coroutine`
- `:datasource:{source,implementation}`
- a `:features:samplefeature:*` stub
- a `MainActivity` that shows "Hello Android" with no navigation

The reference sample `EranBoudjnah/CleanArchitectureForAndroid` (commit 9d99920, 2026-10-20) is newer: AGP 9.4.1 with
built-in Kotlin, Kotlin 2.4.21, Gradle 9.8.2, SDK 37 and Navigation 3. Its module structure, base classes and
`UseCaseExecutor` match the generator's line for line. The only difference is the toolchain and the navigation library.

## Goals / Non-Goals

**Goals:**
- A green build and quality gate that every later change reuses unchanged.
- A project profile (`docs/ARCHITECTURE.md`) that answers every question the skill's Step 0 asks, so feature changes need
  no architectural decisions of their own.
- Generated features (`cag --new-feature`) that compile with no hand-editing of their Gradle files.

**Non-Goals:**
- No database, preferences, billing, analytics or any other datasource code (later changes).
- No end-to-end (instrumentation) test suite yet. The scaffold's `:architecture:instrumentation-test` module stays as
  generated and is first used by a feature change.

## Decisions

### D1. Keep the generator's toolchain for now; plan a dedicated upgrade change

Use the `cag` 0.4.1 versions as generated, with one exception: `minSdk` 26 (see D8).

- **Alternative: the sample's toolchain** (AGP 9.4.1, Kotlin 2.4.21, SDK 37). Rejected for now. AGP 9 provides Kotlin
  itself, but every module `cag` generates applies the `org.jetbrains.kotlin.android` plugin and the classic `android {}`
  DSL. Every future `cag --new-feature` would then need its four Gradle files rewritten by hand. That breaks the goal
  above and the owner's requirement to use the generator.
- **Follow-up:** an `upgrade-toolchain` change moves the project to AGP 9, Kotlin 2.4 and SDK 37 once `cag` supports
  AGP 9, or before Google Play requires target API 37, whichever comes first. Target SDK 36 meets the current Play
  requirement.

### D2. Navigation Compose 2 (type-safe routes), per the skill's `bindings/nav2.md`

Nav2 is the binding used by the book, and `cag` already ships navigation-compose. Feature code is identical under Nav2
and Nav3: features only emit `PresentationNavigationEvent`s. Moving to Nav3 later therefore touches only
`:architecture:ui` and `:app`, and belongs in the D1 upgrade change.

- **Alternative: Nav3 now, as in the sample.** Rejected. It needs Navigation 3 artifacts that the D1 toolchain may not
  support, and it buys nothing for the MVP.
- **Implementation:** routes are `@Serializable` objects and data classes, so the Kotlin serialization plugin is added
  to `:app`.
- This supersedes BRD ADR-03 (Nav3). The BRD is updated in the same change.

### D3. Module layout: the generator's

| Kind | Modules |
|---|---|
| Features | `:features:<feature>:{domain,presentation,data,ui}` |
| Datasources | One pair, `:datasource:source` (JVM interfaces and models) and `:datasource:implementation` (Android). One package per resource, as in the sample |
| Base classes | `:architecture:*` |
| Coroutines | `:coroutine` |

- **Alternative: one module pair per resource** (`:datasource:<x>`), as the BRD module map sketched. Rejected because
  both the sample and `cag --new-datasource` use the single pair. Splitting the pair is a later, local decision if build
  times demand it.
- The BRD section 12 module map is updated to match.

### D4. Failure routing for asynchronous use cases (skill rule 9)

`UseCaseExecutor` catches only exceptions thrown synchronously by `execute()`. `BackgroundExecutingUseCase` runs
`executeInBackground` in a coroutine, so anything thrown there escapes the executor and crashes the app. The sample has
the same code.

The profile fixes the routing:

- Repositories catch datasource exceptions (`*DataException`).
- Expected failures go back to `onResult` as sealed domain results (`…ResultDomainModel` with `Success` and failure
  cases).
- Use cases running in the background never throw.
- A Konsist rule is not practical for this; code review enforces it through the skill's `checklists/review.md`.

- **Alternative: change `UseCase` to carry `onException` into the coroutine.** Rejected. It diverges from both the
  sample and the generator, and every generated use case would need editing.

### D5. UI collection of events

`BaseComposeHolder` collects navigation events and notifications inside one `LaunchedEffect` each, as
`bindings/nav2.md` recommends. With `collectAsState`, two identical events in a row are dropped. If the generated class
uses `collectAsState`, it is changed and the deviation is recorded in the profile.

### D6. UI state holder

Screen state the user edits lives in the composable (`rememberSaveable`). The ViewModel stays stateless (skill rule 4).
This changes nothing in this change and is written into the profile for the feature changes.

### D7. Theme

- The app always uses the dark scheme (a Material 3 `darkColorScheme` with a custom palette) and ignores the system
  setting. A user-selectable theme arrives with the settings change (BRD SET-F1).
- Dynamic colour (Material You) is off, so a bright wallpaper cannot brighten the app.
- **Palette:**
  - near-black background, not pure black (`#0F1115`), to reduce halation;
  - surfaces one or two steps lighter;
  - text in soft grey (around `#C8CCD2`), never `#FFFFFF`;
  - a muted lavender primary accent;
  - a desaturated amber for warnings.
- Edge-to-edge with dark system bars.

### D8. App identity

- `minSdk` = 26 (BRD section 10).
- Label "Migrely", `versionCode` 1, `versionName` "0.1.0".
- `applicationId` stays `com.migrely.app` (ADR-11).
- The merged manifest declares no runtime permissions and no `INTERNET` permission. The billing change adds `INTERNET`
  together with its spec.

### D9. Quality gate

The gate is `./gradlew assembleDebug testDebugUnitTest ktlintCheck detekt`. It runs locally and in GitHub Actions
(`ubuntu-latest`, Temurin JDK 17, Gradle cache).

- Unit tests use JUnit 4 and Mockito-Kotlin, as in the generator and the sample.
- Konsist (0.17.3, the version the skill's templates were verified with) runs inside `:app`'s unit tests. Fallback:
  0.18.1 (the sample's version).

### D10. Home feature

`cag --new-feature --name=Home` generates `:features:home:*`. For this change:

- `HomeViewModel.onEnter()` emits a single `Ready` view state.
- `HomeScreen` shows the app name and a short subtitle.
- The domain and data modules stay empty until change 1 (`add-attack-logging`) adds the quick-log use case to the home
  screen (BRD ATK-F1).
- The generated `samplefeature` stub and its DI module are deleted.

## Risks / Trade-offs

- **[Toolchain falls behind the sample]** → The D1 follow-up change is listed in the BRD plan. The sample remains the
  reference for code, not for versions.
- **[Generated code fails ktlint or detekt out of the box]** → The gate runs in this change. Code is fixed rather than
  rules relaxed, and any rule change is recorded in the profile.
- **[detekt 1.23.8 is older than Kotlin 2.2.20]** → If detekt cannot analyse the sources, bump it to the newest 1.23.x
  or 2.0 release that supports Kotlin 2.2 and record it in the profile.
- **[The "no network requests" scenario has no automated test]** → It is verified by the merged manifest having no
  `INTERNET` permission. Without that permission the app cannot open a socket.
- **[D4 depends on discipline, not tooling]** → The review checklist and repository unit tests that assert failures come
  back as values.

## Migration Plan

Greenfield. Rollback is `git revert` of this change's commit.
